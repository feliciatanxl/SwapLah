## Details of Usage

I declare that I have used Artificial Intelligence (AI) tools to assist in the development of this assignment in the following ways:

1. **Database Schema Design:** Used AI assistance to design the `offers` table, including fields for `listing_id`, `buyer_id`, `offer_type`, `proposed_price`, `swap_listing_id`, `status`, and `created_at`. The schema was reviewed to ensure referential integrity via foreign keys to the `listings` and `users` tables.

2. **Backend API Development:** Used AI assistance to plan and implement the `POST /api/offers` route in `app/routes/offers.py`. This included structuring the handler into focused helper functions (`_validate_common`, `_handle_cash_offer`, `_handle_swap_offer`) to reduce cyclomatic complexity and keep each function single-purpose.

3. **Input Validation Logic:** Used AI assistance to implement validation for both offer types:
   - Cash offers: requiring a non-negative numeric `proposedPrice`.
   - Swap offers: verifying the `swapListingId` exists in the buyer's own active listings.
   - Both: preventing a buyer from submitting an offer on their own listing, and requiring authentication.

4. **Database Helper Functions:** Used AI assistance to implement `get_listing_owner()`, `get_active_listing_by_buyer()`, and `create_offer()` in `app/db.py`. Each function was reviewed and tested to confirm correct SQL behaviour.

5. **Unit Test Creation:** Used AI assistance to write `tests/unit/test_offers_unit.py`. Tests cover all acceptance criteria using monkeypatching to isolate the route layer from the database. Both positive (happy path) and negative (validation failures, ownership checks) scenarios are included.

6. **API Integration Test Creation:** Used AI assistance to write `tests/api/test_offers_api.py`. Tests use a real temporary SQLite database with seeded users and listings, covering all AC for both cash and swap offer flows.

7. **Code Quality Improvements:** Used AI assistance to restructure `offers.py` and `listing.py` to address pylint feedback — correcting import ordering, adding module and function docstrings, reducing boolean expressions in conditionals, and splitting large functions for readability.

8. **Debugging:** Used AI assistance to troubleshoot blueprint registration, session handling in tests, and SQLite foreign key behaviour during development.

## Refinement of AI Output

All AI-generated code was reviewed, tested, and adjusted before inclusion:

- Helper functions were manually traced through to confirm SQL correctness.
- Test cases were extended beyond AI suggestions to cover boundary conditions identified during manual review.
- Pylint and radon output was checked after each change to ensure code quality standards were maintained.
