## Details of Usage

### 1. Test Suite Diagnosis and Repair (Reporting Feature)

Used AI assistance to cross-reference the assignment spec and user stories against the `feature/user-report` branch, and to diagnose why 27 tests were erroring across 4 test files while 203 others passed.

**Root causes identified:**

* Tests calling `create_app(testing=True)`, when `create_app()` in this codebase takes no arguments.
* Raw SQL `INSERT` statements in test fixtures using an incorrect `users` table schema (a `username` column that does not exist — the real schema uses `student_id`, `first_name`, `last_name`, `display_name`).
* Test calls to `create_listing()` missing required positional arguments present in the actual function signature.

**Files rewritten** (to match project test conventions — isolated per-test databases via `monkeypatch.setattr(db_module, "DATABASE", tmp_path/...)`, correct schema, correct function signatures; no production code changed):

* `test_db_reports_unit.py`
* `test_admin_report_unit.py`
* `test_admin_report_api.py`
* `test_listing_report.py`

> This work supports Sprint 5 test items for **US#1** (soft-delete a reported listing) and **US#3** (report an inappropriate listing) — see Sprint 5 test plan §4 (Test Items) and test cases `TC-S5-RPT-001`–`005`, `TC-S5-REMOVE-001`–`004`.

One genuine (pre-existing, non-blocking) logic quirk in `create_report()` was identified and documented rather than silently worked around.

### 2. Codebase Audit for New Feature (User Account Management, US#5–8)

Used AI assistance to audit an existing branch against four new user stories — admin views all users, toggles account status, suspended-login blocking, `/admin/*` route protection — before writing any new code.

**Findings:**

* Suspended-login blocking and server-side `/admin/*` route protection were already fully implemented and tested.
* `app/user_admin.py` already contained correct, schema-accurate `get_all_users()` and `update_user_status()` functions — but these were not called from any route or template, and had zero test coverage.

This audit determined the actual scope of remaining work before any implementation prompts were written, avoiding duplicate or conflicting code.

> Maps to Sprint 5 test plan §4 (Test Items) rows for `GET /admin/users`, `POST /admin/users/<id>/status`, and the `admin_required` role-check decorator (US#5, #6, #8), and to test cases `TC-S5-USR-001`–`003`, `TC-S5-STATUS-001`–`004`, `TC-S5-ADMROUTE-001`–`004`.

### 3. Prompt Engineering for AI-Assisted Implementation

Used AI assistance to write structured, file-specific prompts (for DeepSeek) to implement the identified gap:

* Two new Flask routes: `GET /admin/users`, `POST /admin/users/<id>/status`
* Jinja/JavaScript wiring for the previously static "User Management" tab in `admin.html`
* Accompanying unit and API tests

Each prompt embedded the project's actual existing conventions (route/blueprint style, DB fixture patterns, JS/modal wiring style already used elsewhere in `admin.html`) to reduce the risk of the schema-mismatch errors found in Task 1 recurring.

### 4. CI/CD Pipeline Compliance

Used AI assistance to read and interpret `.gitlab-ci.yml` to identify all blocking quality gates:

| Gate | Requirement |
| --- | --- |
| pylint | Exact score of 10.0/10 |
| `scripts/code_quality_gate.py` | 40-line/function limit and complexity ≤ 10 |
| pytest coverage | `--cov-fail-under=75` on `app/` |
| SAST / secret detection | Must pass with no new findings |

These constraints match the Test Plan's Test Approach (§3) and Exit Criteria (§6): pylint 10.0/10, radon complexity ≤ 10, and ≥75% unit coverage (A-band gate) / ≥60% (assignment minimum). They were folded into the implementation prompts and used as the basis for local verification steps.

### 5. Debugging

Used AI assistance to troubleshoot issues encountered while verifying the branch locally:

* A pylint score of 9.98/10 traced to a missing final newline in `app/user_admin.py`.
* A follow-up mixed-line-endings (`C0327`) pylint error caused by a partial fix that appended an LF-only newline to a CRLF-formatted file; resolved by normalizing the entire file to consistent CRLF line endings rather than patching only the last line.
* Guidance on setting up and running the local test/lint toolchain (`pytest`, `pytest-cov`, `pylint`, `code_quality_gate.py`) to reproduce CI gate results before committing.

### 6. Unit and API Test Creation

Used AI assistance to specify:

Both followed the exact fixture and login-helper patterns already established in `test_admin_authorization.py` and `test_listing_db_unit.py`.

> Corresponds to the Sprint 5 Selenium and API evidence in test plan §8 (`test_admin_user_management_selenium.py`, `test_admin_route_access_selenium.py`) and the "Admin access-control security regression" row in §9 (Regression Testing).

### 7. Code Quality Improvements
